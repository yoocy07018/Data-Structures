std::vector 核心 API 工业级全景图

1. 构造与析构（创建与毁灭）
函数名      语法示例                   底层干了什么？                                                               复杂度
无参构造   vector<int> v;        初始不分配堆内存，三大指针 _First = _Last = _End = nullptr。                        O(1)
容量构造   vector<int> v(n);     一口气开辟n个空间，并调用n次默认构造函数初始化对象。_Last 和 _End 重合。               O(n)
拷贝构造   vector<int> v2(v1);   开辟一块和 v1 一样大的新内存，把 v1 的数据深拷贝过去（大厂非常在乎这里的拷贝开销）      O(n)
析构函数   ~vector();            调用n次析构函数销毁里面所有的对象，然后 delete[] 释放整块堆内存。                      O(n)

2. 容量操作（空间管理员）—— 大厂面试重灾区
函数名                       底层机制与死穴                                                        复杂度
size()       计算公式：_Last - _First。返回当前有多少个真正有效的元素。                               O(1)
capacity()   计算公式：_End - _First。返回当前最多能装多少个元素                                     O(1)
empty()      检查 _First == _Last。比用 size() == 0 效率更高、更泛型。                              O(1)
reserve(n)   预留空间。只改变capacity。若n>capacity触发重新分配内存和元素搬家，但不会创建新对象。       O(n)
resize(n)    重置大小。同时改变 size 和 capacity。如果放不下了会扩容，并用默认值把新格子填满。          O(n)

3.元素访问（增删改查）
a.查（访问）
  vec[i]（下标访问）：底层直接做指针算术（*(_First + i)）。不检查越界，即便你访问了第 100 个格子它也会无脑去读，导致野指针崩溃，但效率极高（O(1)）。
  vec.at(i)：底层同样是访问，但带有越界检查。如果 i >= size()，会抛出 std::out_of_range 异常。为了安全牺牲了一丁点效率（O(1)）。
  front()：返回第一个元素的引用（即 *_First）。
  back()：返回最后一个元素的引用（即 *(_Last - 1)）。
b.增（插入）
  push_back(val)：尾插。如果 _Last < _End，直接在 _Last 位置写入并 ++_Last（O(1)）。如果内存满了，触发重分配扩容机制
  insert(pos, val)：在迭代器 pos 指向的位置插入元素。因为是顺序表，为了腾出空位，pos 后面的所有元素都必须往后乱挪一格。时间复杂度 O(n)
c.删（删除）
  pop_back()：尾删。简单地让 --_Last，并析构被弹出的元素。绝不释放内存（capacity保持不变），效率极高（O(1)）。
  erase(pos)：删除迭代器 pos 位置的元素。被删元素后面的所有对象都必须往前乱挪一格填补空位。
  clear()：清空容器。让 _Last = _First，把里面的对象全部析构掉，但保持内存不释放（capacity不变）（O(n)）。

4.迭代器（遍历接口）
begin()：返回指向第一个元素的迭代器（包装了 _First）。

end()：返回指向最后一个元素后面位置的迭代器（包装了 _Last）。
